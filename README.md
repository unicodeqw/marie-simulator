# Симулятор MARIE

Кросплатформна версія навчального симулятора ЕОМ MARIE до лабораторних робіт №4–5 з курсу «Архітектура комп'ютерів» (кафедра ЕОМ, НУ «Львівська політехніка»): редактор, асемблер, виконання програм і анімація тракту даних в одному застосунку, без Java.

Це порт MarieSim v1.3.01 і MarieDPath (Linda Null, Julia Lobur, «The Essentials of Computer Organization and Architecture»). Поведінку ядра звірено з Java-сирцями оригіналу. Файли програм `.mas` сумісні з оригіналом; старі `.mex` можна відкрити.

- **Веб-версія без встановлення:** https://unicodeqw.github.io/marie-simulator/
- **Десктоп (Windows, macOS, Linux):** інсталятори на сторінці [Releases](https://github.com/unicodeqw/marie-simulator/releases/latest)
- **Без встановлення:** на Windows `*_x64_portable.exe` запускається одразу (потрібен WebView2, він уже є в Windows 10 і 11), на Linux — `*.AppImage`

Інсталятори не підписані сертифікатом розробника. Windows SmartScreen попередить про невідомого видавця: натисніть «Докладніше», потім «Однаково запустити». На macOS відкрийте програму правим кліком і пунктом «Відкрити».

## Інтерфейс

Інтерфейс зроблено за мотивами міні-ЕОМ PDP-8/I з телетайпом ASR-33. Три розділи:

- **Редактор.** Текст програми з підсвіткою синтаксису, кнопка «Асемблювати» (F9), лістинг `.lst` і таблиця символів. Помилки асемблера позначаються на рядках. Після успішного асемблювання програма одразу завантажується в симулятор і в тракт даних.
- **Симулятор.**
  - Передня панель: ряди ламп PC, MAR, MBR, AC, IR, лампи команди й стану. Поруч із кожним регістром — значення і кнопка системи числення (HEX / DEC / ASCII).
  - Клавіші: Пуск, Стоп, Крок, До точки зупинки, Рестарт, Завантажити, Скидання; повзунок затримки від 0 до 3 с.
  - Телетайп: рулон паперу з виводом, поле вводу для команди Input, режими HEX / DEC / ASCII окремо для вводу й виводу.
  - Програма на перфопапері: точки зупинки ставляться кружечками ліворуч від адреси.
  - Пам'ять: усі 4096 слів, комірка операнда останньої команди підсвічується.
- **Тракт даних.** Мнемосхема з регістрами, шиною, ALU та лініями керування. Кожна мікрооперація показується трьома кадрами: підсвітка джерела й приймача, передача значення, гасіння. Є «швидка вибірка», затримка до 30 с і трасування регістрів.

Клавіші: F9 — асемблювати, F5 — пуск, Shift+F5 — стоп, F10 — крок, F1 — система команд, Ctrl+O і Ctrl+S — відкрити і зберегти.

Меню «Файл» відкриває `.mas` і оригінальні `.mex`, зберігає `.mas`, лістинг, таблицю символів і дамп пам'яті (`.dmp`). Мова інтерфейсу — українська або англійська, тема — світла або темна.

## Структура

| Шлях | Що це |
|---|---|
| `sim-core/` | Ядро на Rust без залежностей: асемблер, лістинг, машина, тракт даних, читання `.mex`, core dump. Покрите тестами. |
| `app/tests/` | Тести сховищ інтерфейсу: запуск за таймером, ввід, точки зупинки, трасування. Працюють через справжнє WASM-ядро. |
| `sim-wasm/` | Обгортка `wasm-bindgen`. Ядро працює як WebAssembly і у вебі, і в десктопі. |
| `app/` | Інтерфейс: React 19 + TypeScript + Vite + Tailwind CSS v4 |
| `app/src-tauri/` | Десктопна оболонка Tauri 2: нативні діалоги Відкрити / Зберегти |

## Розробка

Потрібні Rust (stable) з ціллю `wasm32-unknown-unknown` і Node.js 20+. `wasm-pack` ставиться разом з npm-залежностями. Для `npm run check` потрібні ще компоненти `rustfmt` і `clippy`.

```bash
rustup target add wasm32-unknown-unknown
```

```bash
npm install
```

Далі:

```bash
npm run dev            # веб-версія на http://localhost:5173
```

```bash
npm run desktop        # десктопна версія (Tauri)
```

```bash
npm test               # тести ядра (Rust) і сховищ інтерфейсу (vitest)
```

```bash
npm run check          # rustfmt, clippy, oxlint, усі тести й перевірка типів
```

```bash
npm run build:web      # статична збірка в app/dist
```

```bash
npm run build:desktop  # інсталятори в target/release/bundle
```

Іконки застосунку генеруються з `app/public/favicon.svg`:

```bash
npm --prefix app run tauri icon public/favicon.svg
```

## Випуск нової версії

1. Змініть `version` в `app/package.json`: звідти її бере Tauri.
2. Закомітьте зміну, створіть тег `vX.Y.Z` і надішліть його.

Workflow `Release` збере інсталятори для Windows, macOS (Apple Silicon та Intel) і Linux та прикріпить їх до релізу. Веб-версія оновлюється після кожного push у `main` (workflow `Pages`).

## Модель машини

- 4096 слів пам'яті по 16 біт (адреси `000`…`FFF`). Команди й дані лежать в одній пам'яті.
- Команда: 4 біти коду операції і 12 біт адреси.
- Регістри: AC (акумулятор), IR (регістр команд), MBR (буфер пам'яті), IN, OUT — 16 біт; PC (лічильник команд), MAR (адреса пам'яті) — 12 біт.
- Арифметика обгортається за модулем 2¹⁶ без прапорців; PC після `FFF` переходить на `000`.

| Код | Мнемоніка | Дія | Мікрооперації у вкладці «Тракт даних» |
|---|---|---|---|
| `0` | JnS X | `M[X] ← PC`, `PC ← X + 1` | MBR←PC → MAR←X → M[MAR]←MBR → MBR←X → AC←1 → AC←AC+MBR → PC←AC |
| `1` | Load X | `AC ← M[X]` | MAR←X → MBR←M[MAR] → AC←MBR |
| `2` | Store X | `M[X] ← AC` | MAR←X → MBR←AC → M[MAR]←MBR |
| `3` | Add X | `AC ← AC + M[X]` | MAR←X → MBR←M[MAR] → AC←AC+MBR |
| `4` | Subt X | `AC ← AC − M[X]` | MAR←X → MBR←M[MAR] → AC←AC−MBR |
| `5` | Input | `AC ← IN` | AC←IN (машина чекає вводу) |
| `6` | Output | `OUT ← AC` | OUT←AC |
| `7` | Halt | зупинка | — |
| `8` | Skipcond X | пропустити наступну команду за умовою | перевірка IR[11-10] і AC → PC←PC+1 |
| `9` | Jump X | `PC ← X` | PC←IR[11-0] |
| `A` | Clear | `AC ← 0` | AC←0 |
| `B` | AddI X | `AC ← AC + M[M[X]]` | MAR←X → MBR←M[MAR] → MAR←MBR → MBR←M[MAR] → AC←AC+MBR |
| `C` | JumpI X | `PC ← M[X]` | MAR←X → MBR←M[MAR] → PC←MBR |

Кожній команді передує вибірка: `MAR←PC → IR←M[MAR] → PC←PC+1`.

Умову Skipcond задають біти 11–10 операнда: `000` — пропуск, якщо AC < 0; `400` — якщо AC = 0; `800` — якщо AC > 0. Значення `C00` зупиняє машину аварійно. Коди операцій `D`–`F` теж.

### Асемблер

- Рядок: `[мітка,] команда [операнд] [/ коментар]`. Мітки чутливі до регістру літер і не починаються з цифри; мнемоніки — нечутливі.
- Директиви: `ORG` (лише першим рядком, без неї програма починається з `000`), `DEC`, `OCT`, `HEX`, `END`.
- Операнд-адреса — шістнадцяткове число, що починається з цифри: `Add 0F00`. `Add F00` асемблер шукатиме як мітку.
- Константи: `DEC` від −32768 до 32767 (значення до 65535 теж приймаються і зберігаються як 16-бітні), `HEX` від 0 до FFFF.
- Лістинг (`.lst`) і таблиця символів (`.map`) мають формат оригіналу.

### Що уточнено за оригінальною програмою

- **JnS у двох режимах працює по-різному**, як і у двох оригінальних програмах. Симулятор (MarieSim) не чіпає AC. Тракт даних (MarieDPath) виконує RTN з підручника, і AC стає рівним `X + 1`.
- Точка зупинки спрацьовує **після** виконання позначеної команди, а не перед нею.
- Рестарт повертає лише PC; змінена програмою пам'ять лишається. Чисту пам'ять дає повторне завантаження.
- Ввід і вивід типово працюють у режимі ASCII: введене `29` дає `0032`. Для чисел перемкніть режим на DEC.
- У режимі без переносів рядка вивід розриває лише значення 13 в режимі ASCII.
- Текст одразу після коми мітки губиться: `Loop,Load X` — помилка, потрібен пробіл.
- Зайві токени після операнда ігноруються; рядки після `END` не читаються.

### Свідомі відхилення від оригіналу

- Система числення, обрана для показу регістра, не впливає на виконання. В оригіналі IR, MAR, MBR і PC заповнювалися розбором тексту в поточній системі числення, і зміна режиму ламала програму.
- Аварійна зупинка завжди показує причину, зокрема в покроковому режимі та під час виконання до точки зупинки.
- Пуск після Стоп або після точки зупинки продовжує з поточного PC. Повторний Пуск не запускає другий потік.
- `DEC` менше −32768 та `ORG` поза `000`…`FFF` — помилки. Оригінал обгортав перше з неправильним знаком, а друге не перевіряв.
- Порожня програма, крок після скидання та core dump без програми не призводять до збою.
- Нечислове значення на вводі зупиняє машину аварійно і в тракті даних (MarieDPath мовчки записував `FFFF`).
- У тракті даних Output читає AC (в оригіналі лінії читання помилково вказували на IN), а крок після вводу не виконує зайву команду.
- Повторне завантаження програми зберігає точки зупинки.
- Затримку можна вимкнути зовсім: тоді команди виконуються пакетами (в оригіналі мінімум — 10 мс).
- Трасування тракту даних зберігає останні 5000 рядків; оригінал накопичував їх без обмеження.
- У лістингу незібране через помилку слово завжди позначається `?` і `???`; оригінал для директиви без операнда лишав на місці коду пробіл.
- `.mex` лише читається. Формат — Java-серіалізація; читач перевірено на потоці, складеному за специфікацією, а не на файлі з оригінальної програми.
